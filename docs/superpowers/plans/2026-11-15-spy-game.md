# Spy Word Game Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A phone-first web game where a game master deals one word to every player and a related word to a secret spy, players give clues out loud, and one vote decides the round.

**Architecture:** A static Vite site with no framework. All game rules live in one pure module. Room state lives in Firestore; the game master's browser deals words, tallies votes and writes the result, and Firestore security rules keep every player from reading anything but their own word. No Cloud Functions.

**Tech Stack:** Vite, vanilla JavaScript (ES modules), Firebase JS SDK v10+ (Auth anonymous, Firestore), Firebase Hosting, Vitest, `@firebase/rules-unit-testing`, Firebase Emulator Suite (`firebase-tools` as a dev dependency).

**Spec:** `docs/superpowers/specs/2026-11-15-spy-game-design.md` (read it before any task).

## Global Constraints

- Minimum to start a round: 1 game master and 4 players.
- Safe starter: with `n` players, starter index `s`, spy index `p`, safe when `(p - s) mod n >= 2`. One shared function decides this everywhere.
- A player's screen never shows or hints who the spy is before the reveal. All player screens are identical.
- A player's browser must not be able to read another player's word, the spy's id, or any vote from Firestore.
- Tie for most votes, or zero votes: spy wins.
- Removing any player during a round cancels the round and shows the words.
- Word pairs come from `words/word-pairs.json` (array of `[a, b]`); which side goes to the spy is random.
- English interface. No chat, accounts, scoreboard, or multiple spies.
- Node 22 is installed. Java is NOT installed and the Firestore emulator needs it (Task 1).
- Dave's planning checks (previews, money guards, scheduled jobs): none apply. This game has no money, no previews of actions and no scheduled jobs.
- UI work uses the `impeccable` skill; finishing uses `superpowers:verification-before-completion`.

## Review Focus

1. **A player reloads or locks their phone mid-round.** They get the same seat and the same word back, not a new seat. (Task 4 test `rejoin keeps seat and word`)
2. **Names: blank, only spaces, or very long.** Blank is refused; names are trimmed and cut to 20 characters; two players may share a name. (Task 2 test `cleanName`, Task 3 rules test)
3. **Wrong or stale room code.** The join screen says "Room not found" and stays put. (Task 4 test `joinRoom rejects unknown code`)
4. **Voting closed with no votes, or the game master double-taps a button.** No votes means spy wins; a second "Use these words" or "Close voting" does nothing. (Task 2 test `tally of no votes`, Task 4 test `closeVoting twice writes one result`)
5. **Game master types their own words badly.** Blank words or two identical words (ignoring case and spaces) are refused. (Task 2 test `validPair`)

## File Structure

| File | Responsibility |
|---|---|
| `src/game.js` | Pure rules: no Firebase, no DOM |
| `src/firebase.js` | App init, anonymous sign-in, emulator switch |
| `src/room.js` | Every Firestore read and write for a room |
| `src/ui.js` | Renders the current screen from room state, wires buttons |
| `src/main.js` | Entry: sign in, read `?room=` from the URL, subscribe, call `render` |
| `index.html`, `src/style.css` | Shell and styles |
| `firestore.rules` | Access rules |
| `firebase.json`, `.firebaserc` | Hosting and emulator config |
| `tests/game.test.js`, `tests/rules.test.js`, `tests/room.test.js` | Tests |

## Data model (Firestore)

- `rooms/{code}`: `{ gmUid, gmName, phase, round, roundPlayers, starterUid, result }`
  - `phase`: `'lobby' | 'clues' | 'voting' | 'reveal' | 'cancelled'`
  - `roundPlayers`: array of uids in speaking order, frozen when the round is dealt
  - `result` (null until reveal or cancel): `{ votedOutUid, tie, winner, spyUid, common, spy }`
- `rooms/{code}/players/{uid}`: `{ name, joinedAt }` (lobby list, ordered by `joinedAt`)
- `rooms/{code}/private/{uid}`: `{ word, round }`
- `rooms/{code}/gm/secret`: `{ common, spy, spyUid, round }`
- `rooms/{code}/votes/{round}_{uid}`: `{ target, round }`

  expect(pickSpy(P, () => 0.999)).toBe('e');

test('dealPair gives either side to the spy', () => {
  expect(dealPair(['Cola', 'Water'], () => 0)).toEqual({ common: 'Cola', spy: 'Water' });

  expect(cleanName('  Ana ')).toBe('Ana');
  expect(cleanName('   ')).toBeNull();

test('tally: spy caught', () => {
  expect(tally({ a: 'c', b: 'c', d: 'a' }, 'c')).toEqual({ votedOutUid: 'c', tie: false, winner: 'players' });
});

  expect(tally({}, 'c')).toEqual({ votedOutUid: null, tie: true, winner: 'spy' });
});
test('newRoomCode is 4 allowed letters', () => {
  expect(newRoomCode()).toMatch(/^[ABCDEFGHJKMNPQRSTUVWXYZ]{4}$/);
});

### Task 4: Room data layer

**Files:**
- Create: `src/firebase.js`, `src/room.js`
- Test: `tests/room.test.js`

**Interfaces:**
- Consumes: everything from `src/game.js`; rules from Task 3.
- Produces from `src/firebase.js`: `initFirebase(config, { emulator: boolean }): { auth, db }`, `signIn(auth): Promise<string>` (anonymous; returns the uid, the same one after a reload).
- Produces from `src/room.js` (each takes `db` first; `uid` is the caller):
  - `createRoom(db, uid, rawName): Promise<string>` returns the code; retries on a code that already exists.
  - `joinRoom(db, code, uid, rawName): Promise<void>` throws `Error('Room not found')` or `Error('Name needed')`. Joining again with the same uid keeps the original `joinedAt`.
  - `subscribe(db, code, uid, onState): () => void` calls `onState({ room, players, myWord, secret, votesCast })`. `players` is `[{ uid, name }]` by `joinedAt`. `secret` and `votesCast` are filled only for the game master; `myWord` only for a dealt-in player of the current round.
  - `dealRound(db, code, common, spy): Promise<void>` game master only. Refuses under `MIN_PLAYERS`, an invalid pair, or a phase other than `lobby`/`reveal`/`cancelled`. In one batch: `round + 1`, `roundPlayers` = current players, `starterUid: null`, `result: null`, `phase: 'clues'`, a `private` doc per player, `gm/secret` with `pickSpy`.
  - `pickStarter(db, code, starterUid): Promise<void>` throws `Error('Not a safe starter')` unless `starterUid` is in `safeStarters(roundPlayers, spyUid)`; then stores `roundPlayers` as `speakingOrder(...)` and `starterUid`.
  - `openVoting(db, code): Promise<void>` only from `clues` with a starter set.
  - `castVote(db, code, uid, target): Promise<void>`
  - `closeVoting(db, code): Promise<void>` in a transaction: if phase is not `voting`, do nothing; else read `votes/{round}_{uid}` for each uid in `roundPlayers` by id (a transaction cannot run a query), `tally`, write `result` and `phase: 'reveal'`.
  - `removePlayer(db, code, uid): Promise<void>` deletes the player; during `clues` or `voting` also sets `phase: 'cancelled'` and `result` with `winner: null`, the spy and both words.
  - `handOverGm(db, code, newGmUid): Promise<void>` only in `lobby`/`reveal`/`cancelled`: the new game master leaves the player list, the old one joins it.
